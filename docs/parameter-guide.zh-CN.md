# 晶圆缺陷检测：参数说明与内网调参指南

对应项目版本：`0.2.0`。说明依据：当前 `wafer_defects/detector.py`、`cli.py`、`io.py` 与 `image_detection.py`。整理日期：2026-11-05。

本指南的“基线”统一指 `DetectorConfig.for_real_samples()`，即当前 54 张真实脱敏样例使用的配置。它在这批图上得到 40 张正常类无候选、14 张缺陷类均有候选的图像级回归结果；这些图片已经参与调参，尚无完整逐点标注，因此不是新批次的性能保证。

**优先顺序：先确认检测范围和正常背景，再调候选阈值，最后调复核与合并。一次先改一个参数，保留原配置与结果。**

## 1. 迁移时先固定输入和实际配置

### 1.1 输入约定

- 当前真实样例宽 361、高 356；算法不强制这个尺寸。这里所有空间参数均指输入小图的原始像素。
- 输入可以是二维灰度、OpenCV 的 BGR 或 BGRA。来自 Pillow 的 RGB 数组应先转为 BGR。
- 数值范围按 `0～255` 解释。灰度阈值使用这个量程的灰度单位，不是百分比。
- 16 位或 12 位数据应按固定传感器量程转换。例如确定为 12 位有效数据时，可用 `image.astype(np.float32) * (255.0 / 4095.0)`。不要每张图除以各自最大值后再套用同一阈值。
- 不同曝光、增益、锐化、缩放、压缩或显示映射会改变参数适用性。先固定这些条件，再校准检测。
- `x=列、y=行`，原点为左上角；数组索引为 `[y, x]`。图片转置、翻转或重新裁剪后，要重新检查手工圆心和掩膜。

### 1.2 三种入口的配置选择

| 调用方式 | 实际起点 |
| --- | --- |
| `detect(image)` | 当前真实图基线 |
| `detect(image, DetectorConfig.for_real_samples())` | 当前真实图基线 |
| `detect(image, DetectorConfig())` | 保留的通用灵敏配置，**与真实图基线不同** |
| 命令行 `detect`、`batch` 不写 `--preset` | `real` |
| 命令行 `demo` 不写 `--preset` | `sensitive` |
| 命令行同时提供 `--preset`、`--config` | 先选预设，再用 JSON 中出现的键覆盖；没有写出的键继承预设 |
| 新 `image_detection.detect_anomalies()` 不传 `config` | 当前真实图基线，再应用显式传入的兼容参数 |

迁移时推荐使用 [完整真实图配置](../configs/tuning/real-baseline.full.json)，明确固定全部 25 项参数。根目录的 `config.real.json` 是部分覆盖文件，省略项继承所选预设；用它时应搭配 `--preset real`。

```powershell
# 本批图片的基线核对。输出目录放在输入目录之外。
.\.venv\Scripts\python.exe -m wafer_defects batch data --preset real --config configs/tuning/real-baseline.full.json --evaluate-labels --output output/baseline

# 内网生产小图目录不需要预先分好类别。
.\.venv\Scripts\python.exe -m wafer_defects batch "D:\生产小图" --preset real --config configs/tuning/real-baseline.full.json --output output/production
```

Linux 内网可把上述解释器路径替换为 `./.venv/bin/python`，目录换成服务器实际路径；配置 JSON 和检测参数保持相同含义。

Python 中从真实图基线修改参数：

```python
from dataclasses import replace
from wafer_defects import DetectorConfig, detect
from wafer_defects.io import read_image, save_result

baseline = DetectorConfig.for_real_samples()
trial = replace(baseline, min_peak_contrast=24.0)  # 本次先只改这一项。
image = read_image("wafer.png")
result = detect(image, trial)
save_result(image, result, "output/trial_peak24")
```

每张图的 `report.json` 中都有完整 `config`，它是核对实际生效参数的依据。保存代码版本、依赖版本及这份配置，避免只记“我调过某个 JSON”。

## 2. 参数在检测链中的位置

```text
原图
  → 有效区域、外圆与环心
  → 径向曲线 + 圆周稳健背景
  → 残差、按半径估计的噪声
  → 多尺度种子
  → 像素阈值连通域
  → 面积、峰值门槛
  → 局部中值背景交叉复核
  → 近邻重复响应合并
  → 最终候选
```

这是一串联合条件。某处被排除在检测范围外，后面的阈值再低也不会检查它；种子成立也不代表能通过面积、峰值和复核。

### 2.1 全部参数速查

| 参数 | 真实图基线 | 单位或类型 | 主要作用 |
| --- | --- | --- | --- |
| `foreground_threshold` | 3.0 | 灰度 | 自动定位时区分边角背景和可见晶圆 |
| `refine_center` | true | 布尔 | 是否微调明暗环中心 |
| `center_search_radius_px` | 3.0 | 像素 | 环心相对外圆心的单轴最大搜索偏移 |
| `center_exclusion_px` | 4.0 | 像素 | 不检查的中心半径 |

| `angular_samples` | 0 | 整数 | 每个半径的角向采样数；0 自动 |
| `angular_sigma_px` | 4.0 | 弧长像素 | 沿圆周高斯背景平滑的标准差 |

| `confirmation_ksize` | 5 | 0、3、5 | 复核中值窗口边长；0 关闭复核 |

| `confirmation_min_core` | 5.0 | 灰度 | 高响应核心的复核均值下限 |
| `merge_distance_px` | 4.0 | 像素 | 相交候选的近邻去重距离 |

下面出现的试调数值均是**排查用起点**，不是在所有场景都验证有效的推荐范围。

配置中的数值须有限，不能填 NaN、Inf。`radial_step_px`、`angular_sigma_px`、`background_clip_sigma`、`noise_floor`、`noise_bin_width_px`、`seed_score`、`grow_score`、`foreground_threshold` 必须大于 0；其余灰度门槛、复核门槛和搜索/排除/合并距离允许为 0。`background_iterations`、`min_area` 至少为 1，`edge_margin_px` 为非负整数。`angular_samples`、`scales`、`max_area`、`confirmation_ksize` 另有各节所述约束。

JSON 的布尔值写 `true` / `false`，不加引号；取消面积上限写 `null`。`refine_center: "false"` 是字符串，不能当作关闭微调的配置。

## 3. 定位和实际检查范围：5 个参数

### `foreground_threshold`：自动找外圆时的前景灰度差

**定义。** 先从四角估计背景灰度和背景噪声，再判断哪些射线采样点高于背景。它只影响自动定位，不是检测亮斑、暗斑的缺陷阈值。

主射线路径当前使用：

```text
前景阈值 = 边角背景灰度 + max(4.0, foreground_threshold, 6 × 边角噪声估计)
```

- **调大：** 要求边界更明显，可能减少背景噪声造成的外圆干扰；也可能忽略较暗的外缘，使半径缩小或定位失败。
- **调小：** 理论上更容易保留较暗边缘，但主路径有固定 4.0 下限，也受边角噪声项限制；从 3 改成 2 通常不会改变主路径结果。
- **先看什么：** `wafer_geometry` 是否明显偏移或半径不合理。外圈文字、直线边框、严重裁切或背景不再近黑色时，优先检查定位假设。
- **试调：** 怀疑背景杂点参与定位时，可单独试 6、8，并比较外圆。不要用它处理晶圆内部小点漏检。
- **不生效的情况：** 提供了 `geometry` 或 `wafer_mask` 时不走这条自动前景定位。回退轮廓路径的公式没有固定 4.0 项。

### `refine_center`：是否微调明暗环中心

**定义。** 外轮廓给出初始圆心，再在附近寻找圆周灰度更一致的位置。结果保存为 `ring_center_xy`；外轮廓仍保存在 `wafer_geometry`，微调不移动有效区域掩膜。

- **true：** 适合外圆心与内部明暗环中心存在轻微差异的图。
- **false：** 环心直接使用几何圆心，速度更快；适合已经确定几何圆心可靠、微调反而被弱纹理或照明牵动的情况。
- **排查方法：** 对同一张图分别开、关，比较正常交界在 `residual.png` 中是否更干净。
- **限制：** 不是“开了必然更准”。平坦大圆、环很少、明显非同心结构都可能使微调目标不稳定。即使手动给了外圆，true 时仍会继续微调。

### `center_search_radius_px`：环心的搜索范围

**定义。** 当前实现分别限制 `abs(dx)`、`abs(dy)` 不超过该数值。默认 3 表示两个坐标各可偏移 ±3 像素，搜索区域是方形，最大对角位移可达约 4.24 像素。

- **调大：** 可以修正更大的环心偏移，计算量也会上升，并可能找到受非圆背景影响的错误位置。
- **调小：** 更快、偏移更受约束，但可能残留由圆心偏差产生的长圆弧。
- **试调：** 定位大致正确但正常环交界出现成对明暗弧时，可试 4、5；外圆已经偏十几像素时应修正定位，而不是直接扩大搜索。
- **特殊值：** 0 表示跳过微调；`refine_center=false` 时此参数没有作用。
- **实现细节：** 搜索步长固定为 1、0.5、0.25 像素；这不代表最终圆心一定有 0.25 像素的真实精度。

### `center_exclusion_px`：中心不检查的半径

**定义。** 围绕最终环心排除半径小于该值的像素。基线为 4。中心与边缘排除是两种独立限制。

- **调大：** 中心区域的候选会减少，实际检查范围也缩小；无法再发现被排除区域的缺陷。
- **调小：** 可以把更多中心像素纳入检查，但靠近正中心时，同半径参考高度重复，正常中央圆形与缺陷可能无法区分。
- **试调：** 业务要求检查靠近中心的位置时，可先从 4 改到 2，逐图观察背景和候选；不能仅因配置允许 0，就认为正中心已能可靠检测。
- **判据：** 查看 `analysis_mask.png`；黑色表示未检查，不等于已判正常。

### `edge_margin_px`：边缘排除距离

**定义。** 用椭圆结构元素侵蚀有效掩膜。基线为 6。它会收缩外缘，也会扩大自定义掩膜中的无效洞；图像裁切边界同样需要留出空间。

- **调大：** 有效检查范围缩小，可以排除更靠边的细框和业务不关注的变化；近边缘真缺陷也可能被部分截断或全部排除。
- **调小：** 检查范围扩大，边框、缺失插值支撑、极外圈变化的影响更容易进入结果。
- **试调：** 若业务确认最外侧变化无需处理，可试 8、10；要检查距边缘约 5 像素的缺陷，可试 4，并核对圆定位和插值是否可靠。
- **约束：** 非负整数。0 只是不做这次侵蚀，不能保证物理边界处的背景估计可靠。
- **注意：** 扩大排除区降低的是检查覆盖率。比较两套配置时应同时查看检查范围，不能把少检查一圈造成的候选消失直接解释为算法识别更准。

## 4. 正常背景估计：5 个参数

### `radial_step_px`：径向采样间隔

**定义。** 从环心向外，每隔多少原图像素估计一行极坐标背景。默认 0.5。它不是圆环宽度，也不要求各层等宽。

- **调小：** 径向描述更细，有助于窄环和陡峭过渡；内存、计算量大致随 `1 / radial_step_px` 增长。
- **调大：** 更省资源，但可能使窄环或过渡拟合不足，形成环状残差。
- **试调：** 很窄的环先比较 0.5 与 0.25；为了提速可比较 0.5 与 1.0。
- **约束：** 大于 0、且不大于 1。比原像素更密的采样依赖插值，并不创造新的图像细节；也不是越小越准确。

### `angular_samples`：每个半径的角向采样数

**定义。** 一整圈采多少个角度。0 表示自动选择，按最大分析半径的周长留出采样密度，并向上取 2 的幂，最少 512。当前尺寸通常约为 2048。

- **调大：** 圆周取样更密，内存与计算量增大；原图已经充分采样后，继续增大收益很小。
- **调小：** 可以提速，但外圈的弧长采样间隔会增加，几像素的小点可能被削弱。
- **估算：** 半径 `r` 上，相邻采样点的弧长约为 `2πr / angular_samples`。例如 r=180、1024 点时约 1.1 像素；只有 64 点时约 17.7 像素，虽然配置合法，却不适合本任务的小点。
- **建议：** 优先保持 0；有明确资源限制时再试 1024，并检查最外侧弱点。
- **约束：** 0 或至少 64 的整数。这个参数不会改变外圆定位阶段固定的 720 条射线。

### `angular_sigma_px`：沿圆周背景平滑的标准差

**定义。** 按原图弧长计量的高斯标准差，默认 4。它不是 4×4 窗口；高斯影响范围延伸到标准差的数倍。程序会按半径换算角度带宽。

- **调大：** 背景沿圆周变得更平滑，局部小点较难被背景吸收；正常的局部弯曲、环宽变化或照明变化也可能留下更大残差。
- **调小：** 背景更能跟随正常局部变化，可能减少弧形误报；同时也更容易跟随较宽或较弱缺陷，使其残差变小。
- **试调：** 正常窄环处有短弧误报，可比较 4 与 3；缺陷在背景图里也清晰存在、被吸收较多时，可比较 4 与 5、6。
- **联动：** 与 `background_clip_sigma`、迭代次数共同决定缺陷吸收程度。不能只根据缺陷是 5×5 就断言标准差必须大于 5。
- **限制：** 无法靠单个尺度解决明显非同心、局部剧烈扭曲和大面积异常。

### `background_iterations`：背景限幅重估次数

**定义。** 先得到初始圆周平滑背景，再执行指定次数的“估计残差 → 限幅 → 重估”循环。默认 4，循环之前还有一次初始平滑。

- **调大：** 通常能继续降低少数强点对背景的影响，运行时间增加；收益可能趋于稳定，也可能受错误背景假设影响。
- **调小：** 更快，但强异常可能更容易残留在背景中。
- **试调：** 优先在 3、4、6 之间比较。若迭代增加后背景已经不变，继续增加没有必要。
- **约束：** 至少为 1 的整数。它不是检测次数，也不是越多召回越高。

### `background_clip_sigma`：背景重估的限幅倍数

**定义。** 在每个半径上，用稳健噪声尺度给背景样本残差限幅：

```text
样本修正 = 当前背景 + clip(残差, -倍数×尺度, +倍数×尺度)
```

默认倍数为 3。只修改用于拟合背景的样本，不修改实际检测的原图。

- **调大：** 较大偏离也能影响背景，可能更好地跟随正常变化，也更容易把异常拟合进去。
- **调小：** 更强地限制大偏离对背景的影响，有助于保留孤立异常残差；正常但没有被模型解释的结构也可能留下来。
- **试调：** 缺陷被背景吸收时可试 2.5；正常角向变化拟合不足时可比较 3 与 4，但应先检查环心和 `angular_sigma_px`。
- **联动：** 这里的尺度也受 `noise_floor` 影响。提高噪声下限会让限幅区间变宽。

## 5. 噪声估计：2 个参数

### `noise_floor`：噪声标准差下限

**定义。** 不允许估计的标准差低于这个值。默认 1 个灰度。估计来自残差的 MAD，包含相机噪声、纹理和部分模型误差，不是纯相机噪声的物理测量。

- **调大：** 低噪声区域的标准化种子响应降低，像素生长阈值可能升高，复核噪声比可能降低；同时背景限幅范围变宽，缺陷也可能更容易被吸收。
- **调小：** 平坦区域更敏感，但很小的量化、插值或压缩差异可能被放大。
- **试调：** 极平坦区域有零星假点，可比较 1 与 1.5、2；不要只为了找弱点就无依据地降到极小值。
- **限制：** 如果该处 MAD 已明显大于噪声下限，修改下限对该处检测噪声图的影响可能很小。

### `noise_bin_width_px`：按半径估计噪声的分组宽度

**定义。** 每隔多少径向像素计算一组残差 MAD，再插值得到噪声图。默认 6。它对噪声统计分组，不对原图做 6 像素平滑。

- **调大：** 统计更稳定，但可能把噪声不同的明环、暗环或过渡混在一起，让局部阈值不够贴合。
- **调小：** 更能适应不同半径的纹理强度；样本较少时也更容易波动，尤其内圈。
- **试调：** 不同环的噪声差异明显时比较 6 与 3、4；噪声图呈不合理的径向起伏时比较 6 与 8、12。
- **实现细节：** 分组不足 24 个有效像素时回退到全局残差尺度。换参数后，“相同的 seed_score”未必对应相同位置的响应。

## 6. 多尺度种子与连通域：8 个参数

先记两个量：`D = 原图 − 圆环背景`，`σ = 噪声图`。亮点和暗点分别处理；以下绝对值表示两种极性都适用。

### `scales`：种子统计窗口的边长

**定义。** 如 `[1,3,5,7]`，代表对残差使用 1×1、3×3、5×5、7×7 的方形窗口。它不是中值背景窗口，也不是最终候选 bbox 的固定尺寸。

- **增加较大尺度：** 有机会汇总更宽弱异常的响应，也可能增加相关纹理的响应。大窗口包含的正常背景可能稀释小点对比度。
- **增加较小尺度：** 有助于尖锐小点，但孤立坏点和噪声也更容易产生响应。
- **减少尺度：** 可提速、减少某类纹理响应，但可能漏掉原先由该尺度触发的缺陷。
- **试调：** 3～7 像素目标先保留当前设置；更宽目标可先试 `[1,3,5,7,9]`，同时检查中值复核是否会吸收宽缺陷。
- **约束：** 非空、无重复、正奇数列表，最大边长不能大于图像短边。窗口完整落入分析掩膜才有效。

### `seed_score`：标准化种子响应下限

对于完整窗口，主要响应近似为：

```text
种子响应 = sum(D) / sqrt(sum(σ²))
窗口平均残差 = sum(D) / 窗口像素数
```

程序还用噪声下限保护分母。一个窗口必须同时满足：

```text
abs(种子响应) >= seed_score
abs(窗口平均残差) >= min_mean_contrast
```

默认 `seed_score=18`。

- **调大：** 更难产生种子，通常误报减少，弱点可能漏掉。
- **调小：** 更容易产生种子，正常纹理和背景残差也会增加。
- **试调：** 确认背景合理、缺陷没有种子时可比较 18 与 16；大量弱纹理触发时可比较 18 与 20、22。
- **注意：** 独立噪声只是标准化近似，真实纹理会相关。18 不是 18% 概率，也不能解释成严格的 18σ 显著性。不同窗口和不同噪声统计会影响响应。

### `min_mean_contrast`：种子窗口平均对比度下限

**定义。** 对上式窗口平均残差设绝对灰度门槛，默认 2.5，防止大量几乎无实际对比度的像素累加出种子。

- **调大：** 低平均对比度窗口更难通过；也可能漏掉只占大窗口一小部分的点。
- **调小：** 允许更弱的平均变化，相关纹理更容易触发。
- **试调：** 可单独比较 2.5 与 2.0 或 3.0。若 `seed_score` 已经挡住该点，仅降低这个值不会使它通过。
- **区别：** 它作用于种子窗口，不等于最终连通域的 `mean_contrast`，也不是复核参数 `confirmation_min_mean`。

### `grow_score`：连通域像素的噪声倍数门槛

连通域像素必须满足：

```text
abs(D) >= max(grow_score × σ, min_pixel_contrast)
```

同一极性、8 邻接的合格像素组成连通域；连通域还必须含有相应极性的种子。默认倍数为 2.5。

- **调大：** 保留更强的核心，区域通常变小，噪声边缘减少；弱点可能碎裂、面积不足或失去种子。
- **调小：** 区域通常扩大，可能恢复弱边缘；也可能连上周围纹理或其他点，随后因面积太大、峰值变化或复核均值被稀释而被剔除。
- **试调：** 框太碎、只剩几个核心像素时可比较 2.5 与 2.0；区域粘连或扩张太大时可比较 2.5 与 3.0。
- **区别：** 它是逐像素门槛，`seed_score` 是窗口汇总门槛，两者不能直接比较数值大小来判断严格程度。

### `min_pixel_contrast`：连通域像素的绝对灰度门槛

**定义。** 上式中的绝对下限，默认 3。与 `grow_score×σ` 两者取较大值。

- **调大：** 在低噪声区域会减少弱像素和区域面积；可能让小点因面积不足消失。
- **调小：** 低噪声区域会纳入更多弱像素；如果噪声倍数项更大，则调整它没有效果。
- **例子：** `σ=2、grow_score=2.5` 时像素门槛为 5，`min_pixel_contrast` 从 3 改成 2 不会改变这个位置；改成 6 才会把门槛抬到 6。
- **试调：** 先查噪声图，确认绝对项确实在起作用，再比较 3 与 2 或 4。

### `min_area`：连通域最小面积

**定义。** 超过像素门槛的连通域像素数，默认 4。它不是物理缺陷面积，也不是 bbox 的宽×高。

- **调大：** 减少小散点，也更容易漏掉小缺陷或弱缺陷仅剩的核心。
- **调小：** 可以保留更小的区域，也可能重新报出坏点、孤立噪声。
- **试调：** 已知缺陷被截成 3 个有效像素时试 4→3；坏点多且业务只关注较大区域时试 4→6。
- **注意：** 一个可见 5×5 的缺陷并不一定有 25 个超阈值像素。降低面积门槛之前，先确认生长阈值和掩膜没有不合理地截断它。

### `max_area`：连通域最大面积

**定义。** 默认 200，JSON 中 `null` 或 Python 中 `None` 表示取消该上限。

- **调大或取消：** 可以保留较大异常，也可能纳入长弧、大片背景拟合误差或粘连噪声。
- **调小：** 更专注小点，大缺陷、长划痕及连片异常可能被全部排除。
- **试调：** 明确存在面积超过 200 的真实异常时，先查背景是否合理，再试 400；只为定位“是否被面积过滤”可临时设 null。
- **联动：** 降低 `grow_score` 可能让区域超过上限；增加 `max_area` 也不能解决宽缺陷被中值背景吸收的问题。
- **约束：** null 或不小于 `min_area` 的整数。

### `min_peak_contrast`：连通域峰值残差下限

**定义。** 最终区域中，原图相对圆环背景的同极性最大偏差，默认 28。亮点、暗点使用同一绝对值门槛。不是原图最高亮度，也不要求纯白或纯黑。

- **调大：** 更偏向强异常，正常弱变化减少；低对比度缺陷会被挡住。
- **调小：** 允许更弱的异常，但无法自动区分弱缺陷和正常小变化。
- **试调：** 新批次目标只有约 20～25 灰度残差时，先比较 28→24，再决定是否到 20；强缺陷任务但误报较多时可比较 28→32。
- **关键例子：** 一个点的峰值残差只有 24，当前 28 的门槛必然挡住它；单独降低 `seed_score` 没有作用。
- **注意：** `report.json` 只包含最后保留下来的候选。未检出点没有现成的 `peak_contrast` 条目，需要检查精确残差，或在隔离的诊断运行里单独放宽此门槛。

## 7. 局部中值交叉复核：4 个参数

这一阶段同时使用两种背景：圆环背景负责解释正常环结构，局部中值背景提供小范围突变证据。

令 `C = 原图 − 中值背景`，候选极性 `s=+1` 表示亮、`s=-1` 表示暗，候选连通域为 Ω：

```text
复核均值 M = mean(s×C，位置属于 Ω)
复核噪声比 Q = M / max(median(σ，位置属于 Ω), noise_floor)
核心 K = Ω 中满足 s×D >= 0.5×候选峰值 的像素
复核核心均值 H = mean(s×C，位置属于 K)
```

开启复核时，必须同时满足 `M >= confirmation_min_mean`、`Q >= confirmation_min_snr`、`H >= confirmation_min_core`。这些是有符号均值，包含反向证据，不是绝对值均值，也不是 bbox 内最大值。

### `confirmation_ksize`：复核背景的中值窗口

**定义。** 真实基线使用 5×5。当前仅支持 0、3、5；0 关闭整段复核，后面三个复核门槛也随之失效。

- **5→3：** 中值背景更局部，通常更容易跟随较宽的灰度结构；某些窄过渡的误响应会减少，缺陷自身也可能被吸收，复核残差反而减弱。
- **3→5：** 背景可能更能排除小点，但会更受周围窄环结构影响。中值滤波是非线性的，效果不是单调关系。
- **试调：** 开始保持 5。想判断漏检是否由复核造成，可在诊断配置中临时设 0，对比候选；随后恢复并针对复核门槛调整。
- **重要限制：** 当前不能把它直接改成 7、9、21。更宽缺陷可能覆盖窗口的大多数像素，被中值背景跟随；要支持更大窗口或更宽异常，需要扩展实现再验证，不能只增大 `scales` 和 `max_area`。

### `confirmation_min_mean`：整个候选的复核均值门槛

**定义。** 对上式 M 设门槛，默认 3。衡量圆环候选在局部中值残差上是否也有整体同极性支持。

- **调大：** 更容易剔除正常环错位、正负响应混合的候选；弱缺陷或连通域过大的真缺陷也可能被剔除。
- **调小：** 允许更弱、更混杂的局部证据，误报可能增加。
- **试调：** 看见圆环残差上的点、但复核图里同位置变化很弱时，可比较 3→2.5；正常环候选复核均值也偏低时可比较 3→3.5。
- **联动：** `grow_score` 改变 Ω 后，M 也会改变；因此先把连通域范围调合理，再校准这个门槛。

### `confirmation_min_snr`：复核均值相对噪声的比值门槛

**定义。** 对上式 Q 设门槛，默认 1.3。它的分母是圆环残差噪声图的区域中位数，**不是中值残差自身的标准误，也不是缺陷概率**。

- **调大：** 对纹理更强或背景估计更不稳定的区域更保守，可能减少颗粒纹理误报，也可能漏掉纹理上的弱点。
- **调小：** 更容易接受高噪声区域的异常，也会接受更多正常纹理变化。
- **试调：** 颗粒纹理中残留候选时可比较 1.3→1.5、1.6；有明确弱点在强纹理上漏检时可比较 1.3→1.1。
- **例子：** M=3.6、局部 σ=3 时，Q=1.2，未达到 1.3；降低 `confirmation_min_mean` 不会改变这项失败。
- **联动：** 改 `noise_floor`、`noise_bin_width_px` 或背景模型也会改变分母，不应把这些参数各自独立解释。

### `confirmation_min_core`：核心区域的复核均值门槛

**定义。** 对上式 H 设门槛，默认 5。核心由圆环残差达到候选峰值一半的像素组成，要求真正强的位置也得到中值残差支持。

- **调大：** 更难保留“主背景看着很强，但局部背景不认为是突变”的候选；也可能排除黑环缺口或较弱点。
- **调小：** 会保留更多弱核心，也更容易让正常细环的形变通过。
- **试调：** 可单独比较 5→4 或 5→6。
- **区别：** 这是核心均值，不是核心单像素峰值。核心的 0.5 比例是当前代码固定值，不由这个参数控制。

## 8. 结果去重：1 个参数

### `merge_distance_px`：近邻重复响应的抑制距离

**定义。** 默认 4。候选按峰值对比度从高到低排列；两个候选 **bbox 相交且质心距离不超过该值** 时，保留先选中的较强候选。当前实现对相同、不同极性都适用。

- **调大：** 更容易把一处小圈的亮边、暗心当作同一候选；也可能把靠得很近的两个独立缺陷压掉。
- **调小：** 近邻独立缺陷更容易分别保留，同一缺陷也可能重复计数。
- **试调：** 已确认两个独立小点只剩一个时比较 4→2；一处小圈被报两次时，可先检查 bbox 是否相交，再比较 4→5、6。
- **特殊值：** 0 关闭去重。即使距离很近，bbox 不相交也不会合并。
- **注意：** 它不会把两个区域拼成一个大掩膜，而是丢弃重复候选、保留较强候选的区域。调它影响最终数量，不改变背景和原始候选生成过程。

## 9. 从中间结果判断该改哪一层

| 文件或字段 | 应看什么 | 常见误读 |
| --- | --- | --- |
| `analysis_mask.png` | 缺陷位置是否为白色；边缘/中心/无效洞是否符合业务范围 | 黑色区域是未检查，不是已判正常 |
| `background.png` | 正常环是否被保留；缺陷是否被明显吸收；是否错位 | 显示图被截断和取整，定量用 NPZ |
| `residual.png` | 小点是否突出；是否仍有整圈、长弧 | 128 表示 0；显示增益 3，不能把 PNG 灰度当真实残差 |
| `confirmation.png` | 同位置、同极性是否还有局部突变 | 中值背景单独出现环形响应，不代表最终会检出 |
| `score.png` | 多尺度响应的大致分布 | 增益 16 且截断；亮处不代表已通过全部条件 |
| `intermediates.npz` | 精确 `residual/noise_map/score_map/labels` 等 | 没有保存逐尺度响应或被拒候选的全部原因 |
| `report.json → defects` | 最后保留候选的峰值、面积、复核均值等 | 被过滤的点不在列表里，不能据此直接知道卡在哪一关 |
| `peak_score` | 该候选区域的最大 `score_map` 值 | 不是概率，也不是种子成立的充分证据；最大值不记录对应尺度和极性 |
| `touches_analysis_boundary` | 候选是否接触分析范围边缘，可能被截断 | true 不会自动剔除，false 也不是位置可靠性的保证 |

查看一个坐标的精确值：

```python
import numpy as np

x, y = 114, 20  # 示例坐标，换成要排查的小图位置。
with np.load("output/result/intermediates.npz", allow_pickle=False) as data:
    print("是否检查:", bool(data["analysis_mask"][y, x]))

```

## 10. 常见情况与试调顺序

| 新情况 | 先查什么 | 第一步试调 | 后续需要检查 |
| --- | --- | --- | --- |
| 只有极外缘在误报，业务不检查那里 | 外圆是否正确、掩膜是否合理 | `edge_margin_px: 6→8` | 检查范围是否牺牲了近边缘真实缺陷 |
| 正常明暗交界出现整圈或长弧 | 外圆与环心、背景拟合 | 比较 `refine_center` 开关；背景局部跟随不足再试 `angular_sigma_px: 4→3` | 窄环可比较 `radial_step_px: 0.5→0.25`；明显扭曲可能需改模型 |
| 背景合理，但新弱点峰值小于 28 | 精确残差、种子是否存在 | `min_peak_contrast: 28→24` | 仍漏检再分别排查种子和复核门槛 |
| 确实有残差但没有合适种子 | 窗口响应与平均残差 | 单独试 `seed_score: 18→16` | 若平均对比度不足，再单独试 `min_mean_contrast: 2.5→2.0` |
| 小点只剩 2～3 个超阈值像素 | 掩膜、像素生长阈值、噪声 | 确实是面积门槛时试 `min_area: 4→3` | 若区域被切碎，再单独调整 `grow_score` 或 `min_pixel_contrast` |
| 框把正常周围也连进来了 | `grow_score`、噪声、连通域 | `grow_score: 2.5→3.0` | 区域缩小后复核均值、面积也会变化 |
| 颗粒纹理上有假点 | 噪声图是否低估、复核图 | `confirmation_min_snr: 1.3→1.6` | 确认真实弱点未被同时压掉，再考虑种子门槛 |
| 圆环残差有点，中值复核图很弱 | 当前点的复核证据 | 诊断时临时 `confirmation_ksize=0`，与基线对照 | 恢复复核后，根据实际失败项逐个放宽；关闭复核不是直接可用的新配置 |
| 一处小黑圈报出多个框 | 亮边、暗心的位置和 bbox | 检查去重是否开启，再小幅增加 `merge_distance_px` | 太大可能吞掉近邻独立点 |
| 两个相近独立点只报一个 | 原始连通域是否已粘连 | 若由去重导致，`merge_distance_px: 4→2` | 若生成时已粘连，需调像素门槛，单改去重无效 |
| 大缺陷不见了 | 是否被背景吸收、中值背景是否跟随、面积是否超限 | 确认面积超限时临时 `max_area=null` | 宽缺陷超过复核窗口能力时需要扩展算法 |
| 整体变暗/变亮后表现变化 | 曝光、量程、饱和、噪声与通道顺序 | 先统一成像与灰度映射 | 不能仅靠一个阈值适配任意曝光变化 |
| 速度慢 | 分辨率、自动采样数、背景迭代耗时 | 先比较迭代 4→3，或径向步长 0.5→1.0 | 保留最窄环、外圈弱点测试；手工降低角采样也可能丢点 |

### 10.1 对弱点漏检的一个完整排查示例

假设内网新增一个约 5×5 的亮点，当前没有报出：

1. 该位置在 `analysis_mask` 为黑色：先解决检查范围。此时降低 `seed_score` 没有意义。
2. 该位置在范围内，但背景图里也完整出现该亮点：优先比较圆周平滑尺度、背景限幅，不急于降低后级阈值。
3. 原图减背景的峰值约 24：基线峰值门槛 28 会剔除它，可先单独试 24。
4. 峰值达标但只有 3 个合格像素：检查是否需要把面积门槛降到 3，或生长阈值是否过严。
5. 种子与区域都合理，关闭复核的诊断结果能找到它：重新开启复核，计算 M、Q、H，找出实际未通过的那一项。
6. 候选生成正常但最终只剩邻近点：检查是否发生去重，而不是继续降低阈值。

这几个步骤可能同时存在，单改一个门槛不一定立刻出现结果。

## 11. 新旧脚本参数对应和覆盖顺序

以下针对新版 `image_detection.detect_anomalies`：

| 新版入口参数 | 对应关系或行为 |
| --- | --- |
| `config` | 使用传入的 DetectorConfig；省略时使用真实图基线 |
| `boundary_margin` | 非 None 时覆盖 `edge_margin_px` |
| `diff_thresh` | 非 None 时覆盖 `min_peak_contrast`；已不是旧版逐像素绝对差阈值 |
| `min_area` | 非 None 时覆盖同名配置 |
| `max_area` | 非 None 时覆盖同名配置；想取消上限需在 `config` 中设 None |
| `circle_method` | 兼容接受 auto/contour/hough，新版统一稳健自动定位；写 hough 不会切换到旧 Hough |
| `save_diagnostics` | true 导出子目录诊断图和报告；false 仍输出 `<stem>_anomaly.png` |
| `img_path`、`out_dir` | 输入小图与输出路径，不是检测阈值 |

覆盖顺序为：**传入 config 或真实图基线 → 显式的兼容参数覆盖 → 检测**。

尤其注意：原 `split_horizontal` 仍显式调用 `boundary_margin=8`，会覆盖 config 中的 6；当前 54 张样例的汇总采用统一 6 像素配置。切图过程没有修改，但不同入口的实际检查范围可能不同。

```python
from dataclasses import replace
from wafer_defects import DetectorConfig
from image_detection import detect_anomalies

settings = replace(DetectorConfig.for_real_samples(), max_area=None)
points = detect_anomalies("wafer.png", config=settings, out_dir="output/single")
# 若再显式传 boundary_margin=8，则实际边缘距离会覆盖为 8。
```

旧算法保存在 `detect_anomalies_legacy`，仅供对照，其参数不能直接套到新版：

| 旧参数 | 原默认值 | 旧算法作用及迁移注意 |
| --- | --- | --- |
| `median_ksize` | 21 | 整图中值背景边长；新版没有该入口参数，复核窗口仅支持 0/3/5 |
| `diff_thresh` | 25 | 对旧绝对差图逐像素二值化；新版同名参数改为候选峰值门槛 |
| `min_area` / `max_area` | 4 / 1000 | 旧二值差图连通域面积；新版区域来自另一套阈值，数值不能直接等价 |
| `fill_ratio` | 0.15 | 旧连通域面积与 bbox 面积之比；新版没有这个筛选参数 |
| `morph_ksize` | 3 | 旧开运算核边长，0 关闭；新版不再对缺陷二值图做这一步 |
| `boundary_margin` | 1 | 原实现没有实际使用它，而是硬编码 R=177、R_eff=174；新版会实际生效 |
| `circle_method` | contour | 原路由实际上总调用 Hough；新版统一用稳健自动定位 |

旧版 Hough 参数、`MAX_RADIUS` 或硬编码 R=177 不控制新版结果。

## 12. 更换分辨率、倍率或灰度量程时

### 12.1 空间尺寸按 s 倍变化

只有在图像是同一视场、统一缩放且缺陷像素尺寸也随之缩放时，才可把下表作为起点；相机倍率、视场或裁剪同时变化时应重新测量缺陷像素尺寸。

| 参数类型 | 可参考的换算 |
| --- | --- |
| 圆周标准差、中心/边缘距离、环心搜索范围、噪声分组宽度、去重距离 | 初步按 s 倍考虑；整数距离取合理整数 |
| `scales` | 按 s 倍换算为不重复的正奇数，仍需验证窗口是否合适 |
| `min_area`、`max_area` | 初步按 s² 倍考虑；它们统计的是超阈值面积，实际未必严格同比例 |
| `angular_samples` | 优先保持 0，让程序按半径自动选取 |
| `radial_step_px` | 按新图最窄过渡的像素宽度选择，通常先保留 0.5 或试 1.0；当前上限 1，不能机械按 s 倍放大 |
| `confirmation_ksize` | 当前只支持 0/3/5，不能把 5 直接翻倍；宽点复核能力可能需要改实现 |
| 手工圆心、半径、掩膜 | 按实际缩放/裁剪方式重新换算或重新定位，注意像素中心约定 |

灰度门槛不因空间倍率变化就自动乘 s；噪声和响应统计可能变化，需要重新校准。尺寸变大也会增加计算和内存消耗。

### 12.2 灰度做固定线性变换 I′=aI+b

在 `a>0` 且没有饱和截断、没有额外处理的理想条件下，残差和噪声尺度大致随 a 变化，常量偏置 b 通常会被背景消去。

- 需要按 a 检查的灰度参数：`foreground_threshold`、`noise_floor`、`min_pixel_contrast`、`min_mean_contrast`、`min_peak_contrast`、`confirmation_min_mean`、`confirmation_min_core`。
- 倍数或比值参数可先保持：`background_clip_sigma`、`seed_score`、`grow_score`、`confirmation_min_snr`。
- 这只是分析起点；量化、饱和、锐化、非线性映射和相关噪声会破坏简单比例关系。自动定位还有固定 4.0 的灰度下限，不能声称完全具有灰度缩放不变性。

对新设备最稳妥的做法仍是先统一到固定 0～255 物理量程，再用内网代表样本重新标定。

## 13. 当前不由 JSON 控制的实现约定

遇到以下限制时，改 25 个配置参数可能不够，需要修改实现后回归：

| 实现约定 | 当前值与影响 |
| --- | --- |
| 自动外圆射线搜索 | 以图像中心为起点，半径约为短边的 0.2～0.56 倍；严重偏心、裁切或小圆不一定适用 |
| 外圆定位采样 | 720 条射线、径向间隔 0.25 像素，与 `angular_samples`、`radial_step_px` 不是同一参数 |
| 截图直边防护 | 定位时避开约 2～3 像素的图像直边；不随 `edge_margin_px` 变化 |
| 外圆支持条件 | 边界外需还有约 2 像素可见背景；至少 48 条可用射线，拟合阶段至少 32 点 |
| 外圆稳健拟合 | 5 轮，约 3 倍 MAD 剔除，容差下限 0.5 像素 |
| 环心搜索 | 固定 1、0.5、0.25 像素步长；微调目标不是人工确认的真实环心 |
| 噪声估计 | MAD 换算系数 1.4826；分组不足 24 像素时回退全局 |
| 缺陷连通性 | 8 邻接；对角相接的同极性像素会连在一起 |
| 复核核心 | 圆环残差至少达到候选峰值 0.5 倍的像素 |
| 中值窗口支持 | 仅 0/3/5；较大窗口需要扩展实现 |
| 显示图增益 | 残差/复核图 3 倍、零点 128；响应图 16 倍；仅显示，不改变检测阈值 |

手动输入 `geometry=WaferGeometry(cx, cy, radius)` 可绕过自动外圆定位；仍会按 `refine_center` 决定是否微调环心。`wafer_mask` 优先决定有效区域，内部无效洞会保留。

如果同时提供 `wafer_mask` 和 `geometry`，当前代码使用掩膜决定有效像素，并不会自动再与手工圆相交。需要同时限制时，应在调用前自己构造两者的交集。命令行单图支持 `--geometry`、`--mask`；当前 `batch` 入口没有这两个选项，需要逐图自定义几何或掩膜时使用 Python 循环调用 `detect`。

## 15. 内网的一次调参应留下什么

1. 留出本次不参与选参数的后续图片，覆盖不同环数、窄环、亮度、纹理和靠边位置；原 54 张仍保留作回归。
2. 记录确定正常、确定缺陷、业务待确认三种状态。待确认位置不要直接强制当作误报或漏检。
3. 给重点缺陷标近似位置或区域。只用“图片里至少一个框”无法发现同一张图中的其他点被漏掉。
4. 一次先改一项，写明针对的失败阶段，保留基线与新配置的完整报告、覆盖范围和代码版本。
5. 同时检查正常图片误报数、每张图的多余候选、已标注点的匹配情况；边缘覆盖不同的配置要单独比较。
6. 运行回归测试，再用留出的图片复核。已有测试通过说明已知用例未退化，不能替代新场景评估。

```powershell
.\.venv\Scripts\python.exe -W error -m unittest discover -s tests -v
```

当前真实回归测试使用内置的真实图基线。它们不会自动读取你临时传给命令行的试调 JSON；新配置是否合适，应再用该 JSON 跑 `batch` 并检查逐图报告。缺少 `data` 时真实图测试会跳过，不能把跳过解释为内网效果已验证。
